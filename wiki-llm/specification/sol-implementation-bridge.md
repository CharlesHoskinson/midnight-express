# Strict fixture bridge and structural conformance

The reviewed bridge findings are addressed without changing the runtime validator or installed profile bundles. `formal/lean/check.py` now generates 94 typed semantic cases, 3 stateful traces containing 16 steps, `vectors.json`, and `coverage.json`. It rejects stale artifacts unless explicitly run with `--update`; regeneration writes only those three artifacts.

The original accepting fixtures and all 12 previously included negative corpus fixtures remain. Targeted mutations now isolate 52 of the 54 atomic diagnostic conditions. The two exemptions are explicit: an absent source also fails its role and principal checks, and the singleton `Currency.usd` type cannot express unequal currencies. The manifest names every condition and its isolating cases. Every vector's complete failing-condition list is independently kernel-checked in Lean. General theorems in `MidnightExpress/Bridge.lean`, ending with `conj_iff`, connect these diagnostic atoms to the actual Boolean validation gates, so changing a gate cannot silently leave an unrelated diagnostic mirror in place.

Mutations include the actual quantity-times-price cash product above the coefficient bound, lower validity-window failures, invoice-only future occurrence, isolated envelope contract failure, role/principal mismatches, contextual domain/scope/window mismatches, and constructor-representable schema failures. Eighteen additional decimal probes exercise zero, above-bound coefficient, and wrong scale for all six Decimal positions; three accepting probes exercise the upper coefficient boundary. `cash_product_mismatch_at_max_quantity` retains the older case under an accurate name. The real overflow case sets cash to the exact overflowing product, so cash equality holds and the cash bound itself rejects it.

`bridge.py` consumes every object key at every nested level, checks constructor-fixed tags, checks canonical ASCII coefficient syntax, and reconstructs each object from decoded fields to assert exact round trips. Coefficients deliberately have no 18-digit translator limit: the typed model's Nat domain must retain out-of-bound negative tests instead of dropping them at translation. Zero and wrong scales also remain representable. Leading zeros, whitespace, signs, underscores, non-ASCII digits, unsupported singleton tags, missing keys, and unread fields raise rather than being repaired. Control characters use Lean's `\\xHH` escapes; a kernel example compares all ASCII controls, DEL, backslash, quote, and a supplementary Unicode character against their code points. Seven unittest cases exercise these fidelity and fail-closed boundaries.

Every generated Context uses the same finite proposal-commitment table. The table contains proposals appearing anywhere in the cases, fixture context, or stateful traces and their associated contracts; SHA-256 calculation remains trusted Python computation. The function no longer changes to match the single event under test. Its out-of-table empty sentinel is only a finite-fixture convention, not a cryptographic assertion.

The stateful vectors run Python `Harness` and Lean's pure `run`/`structuralCheck` against full events and current contexts. No caller-provided event or intent digests are supplied to Lean. RFQ and invoice traces check fresh input, identical occurrence retry, and another occurrence. The approval trace adds same-action/new-occurrence duplication, changed metadata on the same occurrence, changed expiry and target with matching proposal contexts, expiration, revocation, stale policy after rotation, and a newly rotated policy event. Every changed-intent conflict is also checked as a fresh Python acceptance, proving that its rejection in the trace reaches the replay layer. The complete outcome list and final event/action counts are kernel-checked. Vectors carry the Python rejection category as observational evidence; the category/order is not part of the Lean acceptance specification.

Verification used `/tmp/mpe-data-model-validation-env/bin/python formal/lean/check.py --update`, followed by the normal stale-artifact check. The common proof gate verifies Lean 4.34.1, uses fatal warnings, applies its source policy, and asserts the whole-project axiom audit. Each generated declaration has a finite 2,000,000-heartbeat bound, with `maxRecDepth` 10,000; proof subprocesses have the common gate's 300-second timeout. Measurements describe this machine, not a performance guarantee.

All claimed finite evidence here uses `by decide`, not compiled `#eval` or `native_decide`. A randomized compiled differential was not added to this change. The strict translator, raw JSON parsing, canonical serialization, hashing, signatures, context provenance, concurrent/durable replay, and execution remain outside the Lean proof boundary. The JSON vectors describe decoded typed semantic fixtures; some deliberately invalid or extreme typed Nats exceed the runtime wire grammar, and the vector container is not itself a runtime request body.
