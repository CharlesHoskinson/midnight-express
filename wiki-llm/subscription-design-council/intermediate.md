# Directory findings in progress

These observations precede the council consensus. They describe the incumbent and early reviewer findings, not approved implementation choices.

The incumbent lists event fixtures under Browse streams, while its follow controls subscribe by category. Payment Pending, Final and Reversed examples therefore appear to be separate streams but create the same category watch. A feed descriptor and its event previews need separate presentation and identity.

The optional wallet disclosure and operator controls precede or dominate discovery. The user confirmed a directory as the primary workflow. Connection, delivery inspection and recovery should be findable supporting tasks rather than prerequisites to browsing.

Search currently covers fixture titles and categories. Scaling requires a real catalog model, searchable descriptions and explicit filters, bounded results and a stable selection. Synthetic catalog descriptors must disclose their scope; duplicated aliases cannot imply independent authenticated publishers or contract coverage.

The current runtime intentionally retains one category watch. Organization can persist independently of that runtime, but reload must not reconstitute authority. Reviewers are distinguishing follows, folders, saved searches and read state from delivery, contiguous processing, replay and wallet permission.

## Scope correction

The incumbent six-category watch limit is a defect to address, not a permanent product constraint. The user requested hundreds of feeds and stateful information. A metadata-only catalog harness and saved folder preferences are useful intermediate tests but do not fulfill that request. The target must support independent, explicit local feed scopes and preserve disclosed historical information/read markers while requiring fresh authority before delivery resumes. The usability reviewer is testing this stronger requirement against the earlier conservative proposals.

## Inbox proposal review

The Gemini inbox reviewer supports a desktop split view and mobile drill-down. Its draft also suggests approval actions and disposition rollback. Those suggestions are not adopted: the current demo executes no effects, and a committed processing disposition cannot be reversed casually without changing checkpoint semantics. Reading does not advance delivery or processing positions. The final design must preserve these boundaries regardless of familiar email terminology. Virtualization is a candidate after profiling, not a requirement derived from row count alone.
