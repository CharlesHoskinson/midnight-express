# Agent and event interoperability inventory

Research date: 2026-10-05. Primary pages were fetched with Scrapling; preserved HTML, extracted text, UTC timestamps and SHA-256 digests are under `sources/sol-standards/`. A fetched page's success does not establish implementation conformance. This inventory distinguishes normative protocols, evolving proposals and application frameworks.

## Recommended boundary

Keep the MPE encrypted event/whole-shard receiver as the authoritative network boundary. Use CloudEvents-compatible event metadata **inside authenticated encryption**, AsyncAPI for developer contracts, and a durable local consumer API as the common substrate for human interfaces, wallets, DApps and agents. Add MCP for tool/context integration, A2A only when a consumer needs a remote agent task service, and AG-UI only for an interactive agent frontend. These protocols serve different layers; none supplies MPE privacy, ledger membership, finality or exactly-once business effects.

A local selector must not become a broker filter, public discovery field, webhook registration, remote acknowledgment or recognition-dependent schema/evidence fetch. Transport subscription, local business watch, agent task monitoring and wallet approval are separate objects with separate permissions.

## API consequences

Use server-minted opaque local watch handles scoped to principal/device. A versioned application contract can expose `watch.create`, `watch.list`, `watch.read(handle,cursor,limit)`, `watch.pause`, `watch.resume`, `watch.close`, `consumer.commit` and `action.prepare`. These are proposed application methods, **not MCP standard method names**. A MCP adapter advertises tools with their schemas, exposes watch resources, and maps resource notifications to the current `subscriptions/listen` protocol. Cursor and local commit survive connection loss subject to retention; connection IDs do not become event IDs. Current [MCP subscription mechanics](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/subscriptions) acknowledge the accepted filter, so clients must check partial acceptance; the server retains no subscription state across stdio reconnects. Re-establishing notifications must therefore read durable local state to recover changes.

Return event identity, source/type/schema version, local sequence, cursor, receipt time, expiry, authorization result, provenance and evidence status. Return explicit gap/expired/unknown coverage; quiet reception is not proof of completeness. Provide evidence already cached locally with references. Fetching evidence externally requires a separate authorized privacy-aware operation. `consumer.commit` changes local processing state only; producing a remote receipt is a different explicit action.

Task bindings maintain `{eventSource,eventId,taskId,contextId,artifactId}` relationships without asserting interchangeability. A2A ordered active streams do not by themselves establish a retained MPE event replay history. Push/webhook support requires opt-in endpoint registration, authentication, SSRF defenses, payload minimization, deduplication and an explicit disclosure decision; it is unsuitable as the default private wallet consumer path.

A wallet/DApp capability grant must bind origin/principal, permitted local selectors, retention, readable fields and action scope. Encrypted receipt/decryption, recognized sender, admitted membership, finalized inclusion, business authorization and wallet signature approval remain separate statuses. A notification cannot silently grant a tool the ability to sign or submit a transaction.

## Validation gates

The local reference demo can show watch creation, two consumers, bounded replay, pause/revoke, a gap and one human-approved action using local fixtures. Label its evidence/membership/finality stand-ins. Full protocol requires real whole-shard traces showing that selectors, acknowledgments and evidence fetches are not interest-dependent; pinned MCP/A2A interoperability tests; restart and retention-gap behavior; isolation between principals; and action idempotency plus wallet authorization. Do not promote a convenient SDK integration to a full-protocol claim.

## Evidence limitations

Official current pages can change without a new MCP protocol date when changes remain compatible; corpus hashes identify the exact researched content. `latest` A2A and ANP main are moving targets and must be pinned for implementation. Initial MCP historical research was corrected after checking the current versioning page; historical files are retained to document the migration risk. Screenshot grounding status is reported in the agent report; source fetch success alone is not visual verification.

## Independent review refinements

The [Opus agent review](agents/opus-agent-experience.md) independently verified the current MCP profile and adds implementation consequences: notification loss requires bounded reads on reconnect; authorization binds each request, not a connection; private resource results require private cache scope; and sender text cannot become tools or instructions. Host-mediated input requests belong to an originating client request. A arriving event cannot itself force an MCP human prompt.

MCP Apps is an additional candidate for supervision inside an agent host, while AG-UI serves custom frontend interactions. Neither approval UI supplies business authority. The review pinned A2A v1.0.1 and emphasizes task-terminal stream behavior. Actual host support, SDK choice and sandbox-origin isolation require interoperability tests. Do not connect Moth inside an unverified shared host sandbox.

This inventory covers relevant protocols, identity formats, extensions and frameworks discovered in this survey. It is not a guarantee that every emerging agent proposal has been found or implemented. Archived versions remain evidence of the documents read, not requirements to adopt all candidates.

The [Grok data study](agents/grok-data-utility.md) additionally fetched AsyncAPI 3.1.0 at its release tag. The earlier 3.0 source remains the original survey pin, not a claim of latest release. Defer a production AsyncAPI artifact until the local control-plane contract is accepted. The same study found the separate CloudEvents Subscriptions API at 0.1-wip; it is not included in the released CloudEvents 1.0.2 core and is not selected for MPE. CESQL remains an evaluated alternative, not an installed selector engine.
