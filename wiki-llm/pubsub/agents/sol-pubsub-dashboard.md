# Local dashboard implementation

Built native static HTML/CSS/JavaScript at `website/dist/subscriptions.html`, with a local JSON fixture manifest. Reused the existing site stylesheet and Moth adapter. Read subscription-contracts.md and wallet-consumers.md plus the actual connector implementation. No additional external claims or source retrieval were necessary: the implementation follows those separately researched boundaries.

The first usable prototype provides six category streams, text/category browsing, four consumer views, local scope revisions, pause/resume/tombstones, simulated delivery and explicit processing, duplicate occurrence suppression, bounded demand, quarantine, retention-gap acceptance, expiry/revocation and nonsensitive export. Fixture data copies current model examples and trusted test context rather than inventing events. No sealed wire is fabricated. The shipped manifest embeds genuine offline validator receipts from data-model-fit.json for exact event/context objects. The UI labels these as offline references with unverified live source/permission. An expired-context quote negative fixture demonstrates quarantine. Browser code never runs or imitates the validator.

Chosen memory-only state prevents misleading durable receipts: reload/reset clears demo state. Two in-flight credits, four queued records, 16 KiB queue and 64 original journal records stop scheduling/intake at capacity. Undecided originals are not evicted. Queue exhaustion visibly gaps scheduling while retained originals remain available from cursor 1. Explicit recovery fills bounded credits from those originals; processing decisions free demand for further recovery. Synthetic retention gaps deliberately make their range unavailable and require explicit new intent revision. Gap acceptance requires deciding queued/in-flight work before setting an exported exclusive after-cursor. The dashboard has no external replay archive. The processing checkpoint advances only through recorded relevant dispositions. Real persistence, crash-safe atomic checkpoints, conflict validation and arbitrary source predicates remain deployment work; no global exactly-once guarantee is made.

An IndexedDB adapter and general expression editor were considered but excluded: they would enlarge the prototype while implying persistence or programmable selectors without implemented permission/validation services. A category scope editor is sufficient to demonstrate local-only routing and revision boundaries. Wallet connection remains independent of every subscription permission. Discovery/connect/status only happen from explicit buttons; local disconnect discards the handle and cannot revoke Moth origin grants.

Behavior checked with permanent self-serving Playwright script `website/tests/subscriptions.cjs`: revoked/expired lifecycle guards, blocked duplicate or gapped scope edits, bounded retained replay, pause/resume, exported intent history and after-cursor, revision checkpoint boundaries, unsigned delivery and processing, retention gap and explicit acceptance, revoked intake, offline quote review plus expired-context quarantine, duplicate replay suppression, 390px viewport at 200% font size without overflow, no script errors. Node syntax check passed. These checks use synthetic local demo state, not a live wallet or transport. Scope revisions require cleared queued/in-flight work and capture a new journal boundary, preserving the meaning of existing receipt records. Runtime expiry/revocation never rewrites requested intent state.

Further review fixed paused-intent saturation: a gapped runtime cannot dispatch while requestedState remains paused. Bounded recovery preserves the paused request and requires explicit Resume before credits deliver. Permanent tests cover this saturation/recovery boundary. Exported synthetic receipt dispositions include subscriptionId and intent revision, distinguishing consumers and retained historical scope.
