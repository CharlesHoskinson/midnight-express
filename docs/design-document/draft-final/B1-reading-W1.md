## Bitmessage and its successors

@2012-warren-bitmessage-whitepaper :: The founding proposal for Bitmessage. Every node receives every object and tries to decrypt each message with each of its keys (trial decryption), so an observer cannot tell which node was the recipient. Spam is held back only by a hash proof of work, set so that an average computer spends about four minutes on a typical message. Nodes keep objects for two days. As load grows, the network splits into streams, separate sub-networks, and each split shrinks the anonymity set, the nodes among which the recipient hides. Midnight Express inherits this pattern of fixed retention, local recognition and a cost to publish, and tries to make it cheaper to run. The paper is a proposal only and reports no measurement or analysis.

@2012-bitmessage-protocol-specification :: The wire specification of Bitmessage protocol version 3. An object may be at most 2^18 bytes (262,144 B) and must expire no more than 28 days plus 3 hours ahead. Each recipient sets the proof-of-work difficulty in its public key through two parameters, both with a network minimum of 1,000. Version 4 public keys and version 5 broadcasts carry a 32-byte tag derived from the sender's address, which lets subscribers recognise a broadcast without trial decryption. Because the tag never changes for a given address, an observer can link every broadcast from it. Midnight Express removes that link by salting afresh the 16-byte Recognition Tag of each MPE Envelope, the fixed-size sealed unit that Bus Nodes relay. The document records PyBitmessage behaviour and is not an independent standard.

@2015-schaub-bitmessage-antispam :: An analysis of Bitmessage's proof of work. Its difficulty target grows with message length but only linearly with time to live (TTL), and a spammer, who wants as many messages as possible persisting at once, therefore always gains from a longer lifetime. Raising the TTL term to an exponent of 1.64 makes work outgrow lifetime and roughly halves persistent spam, while a desktop user still sends in one second. Relays cannot enforce a per-sender rate, the paper notes, because the sender is encrypted. Midnight Express meets that obstruction with membership quotas instead of hash work. The work is a course project with no implementation, and its hash rates are assumed from Bitcoin figures.

@2017-eip-627-whisper :: The specification of Ethereum's Whisper, the direct successor of Bitmessage, which was later abandoned for Waku. An envelope carries expiry, time to live, a 4-byte topic, encrypted data and a nonce, and proof of work is scored per byte per second of life. To save bandwidth, a node can advertise a 512-bit Bloom filter of its topics, with up to three bits set per topic, so that peers forward only matching envelopes. Any peer that reads the filter learns a superset of the node's interests. The specification asserts, without analysis, that the filter does not compromise privacy "too much". Midnight Express rejects per-topic filters and instead uses Shards (traffic partitions, each received whole) and fixed size classes.

@2018-ethersphere-pss-readme :: The README of Postal Services over Swarm (pss). A message is routed towards a full or partial overlay address; every node in the target neighbourhood tries to decrypt it, and nodes that succeed keep forwarding it to frustrate traffic analysis. An empty address floods the whole network. The prefix length is therefore the receiver-privacy setting. A shorter prefix gives a larger anonymity set and costs more decryption and bandwidth, which is the trade-off the number of Shards sets in Midnight Express. Delivery is best effort, and duplicates are possible. The README describes a protocol still under development and offers no analysis.

@2018-grigg-zip307-light-client :: The Zcash light-client protocol. Its security goal is payment detection privacy: an honest-but-curious proxy, one that follows the protocol but studies what it sees, must not learn which transactions belong to a wallet. Clients download compact blocks and trial-decrypt only the first 52 bytes of each output ciphertext. The stream per output falls from 580 to 116 bytes, an 80 percent saving, and spends shrink to 32 bytes, a 90 percent saving. The protocol is the deployed precedent for whole-Shard download with local recognition, which costs a Midnight Express Subscriber about 1.86 GB per day at the baseline mix of Chapter 9 (derived). Its guarantee lasts only while the client fetches everything. Unlinking the client's queries assumes network privacy such as Tor.

@2019-erturk-anonymous-stochastic-routing :: A game-theoretic model in which an agent routes to a hidden goal while an adversary watches the whole path and tries to name the goal. Water-filling strategies hide intended moves among random ones and give a prediction risk of order 1/(delay minus a noise cost), so noise adds only a fixed delay. The bound is tight on complete graphs and holds for a family that includes Erdős-Rényi graphs. The baseline is Bitmessage-style flooding, which hands every malicious node a copy. Applied to Midnight Express, the model says that receiver privacy without flooding can be bought with added delay. It is stylised and asymptotic, with one agent and neither cover traffic nor cryptography.

@2020-vac-waku2-relay-spec :: Waku v2's relay layer. It runs GossipSub, the libp2p publish/subscribe protocol that forwards each message to a small mesh of peers, under the StrictNoSign policy, so messages carry no author, sequence number, signature or key fields. The two stated goals are publisher-message and subscriber-topic unlinkability. For the second, the specification recommends one shared topic so that subscribers are k-anonymous, hidden among at least k candidates, with k proportional to network size. It admits that a publisher's direct peers may still identify its messages by traffic analysis. Waku relay is the closest relative of Midnight Express, with the same transport, unsigned messages and anonymity sets bounded by Shards. Its security analysis is a few informal paragraphs, and the k-anonymity claim is not measured.

@2021-shi-bitmessage-plus :: A redesign of Bitmessage published in IEEE Access. Proof of space replaces hash work, delivered messages are stored as blockchain transactions, and each message goes to a stealth address, a one-time address derived from the receiver's public key, so the receiver tests each address instead of decrypting every message. The paper argues for the ledger as the message carrier. Midnight Express rejects that for Message bodies because of size, cost and finality, and keeps the ledger only for the ledger lane, its slower path through Midnight transactions. The authors state that the protocol was never implemented; the paper quantifies neither throughput nor storage cost.

@2021-vac-waku2-rln-relay-spec :: Waku's admission layer, based on rate-limiting nullifiers. A member proves in zero knowledge that it belongs to a Merkle tree registered on chain and attaches a nullifier fixed by its key and the epoch, Waku's fixed time window. Each message also carries a Shamir share of the key. Two messages in the same epoch reveal two shares, and two shares give up the secret key and with it the member's stake. Relays accept proofs against a window of recent roots (the tree's last few states) and reject epochs too far from their own clock. The Admission Proof in Midnight Express follows this model and shares its limit: each relay detects double use only among the messages it has seen, so a network-wide quota cannot be enforced. Stake-based slashing has no direct Midnight equivalent, because DUST, the fee resource that holding NIGHT generates, cannot be transferred.

@2023-kovacs-umbra-anonymity :: An on-chain measurement of Umbra stealth payments on Ethereum and three layer-2 chains. Umbra recipients scan every announcement or delegate scanning to a trusted party. Simple heuristics, chiefly withdrawal to the registrant's own address, identify the real recipient of 48.5, 25.8, 65.7 and 52.6 percent of transactions on mainnet, Polygon, Arbitrum and Optimism. The paper argues against trusting cryptographic receiver privacy alone, since what a recipient does after recognition undoes it. In Midnight Express the analogue is a Consumer's visible contract call after a Message. The adversary sees only the chain, and the heuristics can give false positives.

@nostr-nip-17 :: The current Nostr scheme for private direct messages. A sealed message is wrapped under a one-time key, its timestamp is randomised up to two days into the past, and it goes only to the one to three inbox relays (storage servers) that the recipient lists. Relays should serve wrapped events only to the authenticated recipient. A relay therefore never sees the sender but always knows the recipient, the reverse of the property Midnight Express wants for Subscribers. Random keys, the specification warns, defeat reputation-based spam filtering. Protection depends on relays enforcing authentication, and no analysis is given.

@2024-wei-nostr-empirical :: A six-month measurement of Nostr in 2023: 17.8 million posts, 1.5 million keys and 712 relays. Of the posts, 93 percent sit on several relays, with 34.6 copies on average, and 98.2 percent of retrievals are redundant. A fifth of relays were down for more than 40 percent of the period, and 95 percent of free relays cannot cover their costs from donations. Capping replication saves 61.7 percent of copies. Store Nodes face the same operator economics and replication overhead, as would an external publish/subscribe service. The paper measures public posts only, not direct messages.

@2025-upadhyay-efpix :: A 2025 single-author preprint that revives Bitmessage-style flooding. Packets carry proof of work and are deduplicated by a hash that excludes the nonce, a maximum age limits replay, and every node relays each packet before trying to decrypt it. The example packet is a fixed 424 bytes holding a 256-byte message. Optional flooding by sector or time to live is said to trade anonymity for scale. The flood-everything design is thus still being proposed, whereas Midnight Express settles its trade-off between anonymity and scale with Shards. The paper gives no implementation results or measurements.

## Definitions, theory, bounds and surveys

@2010-pfitzmann-terminology :: The standard vocabulary of anonymous communication (version 0.34). Anonymity is defined as not being identifiable within an anonymity set, measured from a stated attacker's perspective. Unlinkability and undetectability are defined there too, as are unobservability and pseudonymity; two items are unlinkable when the attacker cannot sufficiently tell whether they are related. Midnight Express takes its property names from here. Interest-hiding is unlinkability of a Subscriber to the Recognition Tags it recognises, as seen by a Bus Node or Store Node. The design does not claim unobservability, since anyone watching a Shard sees its MPE Envelopes. The terminology gives definitions, not a model or proof, and assumes that message content reveals nothing about sender or recipient, which sealing must provide.

@2013-gelernter-limits-provable-anonymity :: A workshop paper (WPES 2013) that gives indistinguishability definitions for anonymity against malicious peers and a malicious destination: no attacker may distinguish runs that differ only in who sent. Its lower bound covers any protocol whose senders stay anonymous to a destination that also eavesdrops globally. Since a sender's traffic cannot depend on what it has to send, delivered messages cannot exceed the transmissions of the least active honest sender, and total traffic is at least output times the number of honest senders. Achieving the full notion requires secure multiparty computation. Midnight Express does not offer sender anonymity against a global observer, and the bound gives the reason: every member would have to send all the time. The model is synchronous, with instantaneous computation.

@2013-oya-sda-family :: A unified framework for statistical disclosure attacks on threshold mixes, which shuffle and send fixed-size batches. The attacks intersect many batches to learn each sender's usual recipients. Two improved estimators beat the original attack, and a least-squares estimator does better still unless all users have the same sending profile. Error falls in inverse proportion to the number of mixing periods observed. Per-message ambiguity is therefore no defence for a Subscriber or Consumer who acts repeatedly: intersection profiles them, however good each MPE Envelope is. Midnight Express accordingly makes no claim to relationship privacy at launch. The analysis covers one threshold mix and stationary users, and the results are asymptotic.

@2014-oya-dummies :: A study of the limits of dummy traffic against a global passive observer who profiles senders by least squares. Sender dummies always raise the observer's error, but with diminishing returns when one user protects themself alone. Dummies sent by the mix itself can protect chosen receivers, and in the worked example the best split put about 40 percent of dummies at senders and 60 percent at the mix. Optional, per-client cover MPE Envelopes would therefore buy Midnight Express little. Cover has to be collective and planned to matter. Users are assumed stationary, independent and memoryless, and only one kind of pool mix is analysed.

@2015-unger-sok-securemessaging :: The IEEE S&P 2015 systematisation of secure messaging. It splits the field into trust establishment, conversation security and transport privacy, and finds transport privacy hardest to provide without large performance penalties. Sending everything to everyone is the only approach it rates as giving recipient anonymity, participation anonymity and unlinkability against all network attackers. The costs are bandwidth and scale, and splitting into broadcast groups shrinks the anonymity set. Bitmessage is cited as needing proof of work or fees. These ratings frame the Shard trade-off in Midnight Express. They come from expert walkthroughs, not user studies, and date from 2015.

@2018-shirazi-survey-routing-anon :: A survey that classifies anonymous-communication protocols by routing: network structure, routing information and communication model. Choosing relays uniformly usually gives better anonymity, it finds, while weighted choice gives better performance. Each family is paired with its typical adversary and weakness: flooding attacks for mixnets, timing for onion routing, partitioning for distributed hash tables, and collisions for DC-nets. DC-nets (dining-cryptographers networks) such as Dissent scale to a few thousand clients. Peer selection in the Midnight Express mesh sits on the same axis, uniformity against performance. The survey covers routing only and treats gossip only as a way to discover nodes.

@2017-das-trilemma :: The anonymity trilemma. Let ℓ be the latency overhead (the rounds a message may wait) and β the fraction of users sending dummy traffic (noise) per round. Against a global passive observer, no protocol achieves strong sender or recipient anonymity when 2ℓβ < 1, up to a negligible term. Delivery within one round (ℓ = 1), for instance, needs at least half the users sending noise in every round. Compromised relays tighten the condition. A low-latency gossip system without cover traffic, such as Midnight Express, therefore cannot claim to hide publishers or recipients from a global observer, and the design accepts that limit. The bounds are necessary conditions, not sufficient ones, and assume each message is transmitted directly from sender to recipient.

@2018-angel-little-leakage :: A short workshop paper presenting the compromised-friend attack on metadata-private messaging. Each client can hold only a fixed number of conversations, so a compromised contact who dials can learn whether the user is busy. That one bit enables existing intersection attacks against deployed systems. The proposed fix, answering calls on a fixed schedule, still reveals the user's chosen bound and adds latency. Small, repeated leaks, the paper argues, defeat strong per-message guarantees. For Midnight Express the comparable leak is a Consumer's observable reaction to a Message. The work targets dialing protocols, not publish/subscribe.

@2020-kuhn-sokperformance :: A systematisation (WPES 2020) of four lower bounds on the overhead of anonymity. It shows that two of them are equivalent and orders all four by the overhead they require. One of them, the Dropping-Bound (drop a suspect's packets and see whether a message still arrives), applies already to sender-receiver unlinkability. The paper also narrows the trilemma [@2017-das-trilemma] to sender-message unlinkability, one of the weakest notions: the observer must not learn which of two senders sent which message. Every bound assumes a single anonymity set of all users. The Counting-Bound and the trilemma assume an adversary that eavesdrops on the links of the suspected senders and of the receiver; the Dropping-Bound assumes an active adversary that drops a suspect's packets and, as the paper's erratum states, corrupts the receiver so that it can tell real messages from dummies. For Midnight Express the paper shows which bound governs which property. It also shows why sharding falls outside the bounds' assumptions: a Subscriber hides only among the readers of its Shard. Sender goals are in the main text and receiver goals in an appendix.

@2023-guerraoui-inherent-anonymity-gossiping :: A theory paper on how well gossip hides its source, framed as differential privacy against curious nodes: nothing they observe may be more than e^ε times likelier under one candidate source than another. With f curious nodes, any gossip protocol has ε at least ln(f − 1). If the graph's vertex connectivity, the fewest nodes whose removal disconnects it, is at most f, the curious nodes can occupy such a cut, and no finite ε is possible. Positive results need random walks, Dandelion-style forwarding (a single path, then broadcast) or muted forwarding. Standard push gossip, where every holder forwards at once, falls outside them, and broader spreading gives vacuous guarantees. Midnight Express should therefore not expect source privacy from GossipSub's eager push to eight mesh peers. The model assumes regular expander graphs, an unknown start time and content that reveals nothing.

@2023-sasy-sokmetadata :: A systematisation of 31 metadata-protecting systems designed against a global adversary, sorted by the property they give and by technique (DC-nets, mixnets, differential privacy, private retrieval, secure computation). Its low-latency target is 10 s for more than 100,000 clients. By that measure only eight systems are low-latency, and none combines low latency, asynchrony and horizontal scaling. Servers able to exclude clients, helped by Sybils, can shrink anonymity sets even in the strongest designs. For Midnight Express the survey supports leaving the global observer out of scope at launch. It excludes peer-to-peer networks, and its performance figures are not comparable across systems.

@2024-frank-anonymous-messaging-altruism :: A game-theoretic study of fuzzy message detection. Each user chooses a false-positive rate, and those false positives are cover for others, since the server also forwards that share of others' messages. Because a user's privacy depends only on others' rates, the selfish equilibrium has no cover at all. A viable equilibrium needs a few altruists: in two real communication graphs, a handful of central nodes carry most of the cover. The result argues against relying on fuzzy detection with user-chosen rates. Midnight Express does not use fuzzy detection clues, even for first contact, which by default uses authenticated invitations (`DEC-020` in the decision register). The model is a one-shot game with perfect information, solved numerically on two datasets.
