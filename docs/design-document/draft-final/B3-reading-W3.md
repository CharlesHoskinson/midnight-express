## GossipSub, libp2p and gossip security

A GossipSub peer sends each message in full to its mesh (a few peers, kept between D_low and D_high around a target D) and gossips only message identifiers to the rest. GRAFT and PRUNE add and remove mesh links, chosen by a local score of each peer. An eclipse attack fills every connection slot of a victim with attacker-controlled peers, which then choose what it sees. A Bus Node therefore needs at least one honest path into its Shard's mesh, in steady state and after a restart. Published attacks cut that path in three ways: peer tables an attacker can fill, identifiers that cost nothing, and trimming scores an attacker can inflate. None settles how peer scores behave when a relay can check an Envelope's admission and format but not its content.

@2015-heilman-eclipse :: The first systematic eclipse attack on a deployed cryptocurrency overlay targets Bitcoin's address tables, "tried" and "new", bucketed by IP prefix. An attacker who filled them could take all eight outgoing connections, and up to 117 incoming ones, when the victim restarted. An infrastructure attacker with 32 distinct /24 blocks, or a botnet of 4,600 bots, eclipses a victim with at least 85 percent probability; 400 bots sufficed against live nodes. For Bus Nodes, restart is the vulnerable moment and peer tables need diversity rules. Caveat: Bitcoin's 2015 address manager, since patched with the paper's countermeasures.
@2018-marcus-ethereumeclipse :: These eclipse attacks on Ethereum's Kademlia-based neighbour discovery need only two hosts with one IP address each. Many node identifiers could run behind one address, so the attacker could fill the victim's discovery table, take every connection slot on reboot and filter its view of the chain. The first countermeasure, a limit on unsolicited incoming connections, shipped in geth 1.8.0 in February 2018; a one-to-one mapping of IP address to identifier was not adopted as proposed. Bus Node discovery runs on a libp2p overlay where peer keys are free, so it cannot treat peer identifiers as scarce. Caveat: the 2018 geth client, before proof of stake.
@2020-vyzovitis-gossipsub :: The GossipSub v1.1 design paper combines an eager-push mesh, lazy-pull gossip of identifiers beyond it and a per-peer score, and gives each part its own mitigation. Its testbed ran 1,000 honest nodes and 4,000 Sybils at 120 messages per second; each Sybil could open 100 connections and each honest node up to 20, a 20:1 connection ratio (400,000 against 20,000). Under a network-wide eclipse attempt no messages were lost and p99 latency stayed at 141 ms. This document adopts its mesh parameters (D = 8, D_low = 6, D_high = 12). Caveat: the designers evaluated their own protocol on block workloads, which every node can check against chain state; a relay can judge a sealed Envelope only by its admission and format.
@2020-gossipsub-v11-spec :: The normative libp2p specification of GossipSub v1.1 covers prune backoff with peer exchange, flood publishing, adaptive gossip and an outbound mesh quota (D_out). It defines a score from time in mesh, first deliveries, mesh delivery deficits, invalid messages, an application score, IP colocation and a behaviour penalty. Extended validators return Accept, Reject or Ignore, and only Reject is penalised; the Bus Node validation pipeline implements that interface. An Envelope a node Ignores is lost at that node: later copies are dropped too, and the sender is told nothing. A Bus Node runs into this after a restart. It remembers the admission nullifier of each Envelope it admits, a value that repeats if a membership spends one credit (the right to one Envelope in a 60-second admission window) twice, and a restart erases that record. So for 140 s after every start (two admission windows plus 20 s of tolerance), its restart barrier, the node Ignores new admissions and answers a publishing client with an explicit Busy reply, and the client moves at once to another Bus Node. Busy is a publish-service reply, not a GossipSub validation outcome. Caveat: the specification sets no default weights, and v1.2 adds IDONTWANT.
@2020-leastauthority-gossipsub-audit :: This independent audit of the v1.1 design and its Go implementation dates from June 2020. It reports four issues, three since resolved. A man in the middle could fake IP colocation to lower honest peers' scores. In "love bombing", Sybils with a faster route from publishers inflate their first-delivery scores to displace honest mesh peers. "Graft sniping" made love bombing cheaper, because a peer accepted every GRAFT and pruned only at its next heartbeat. Insecure peer discovery, the fourth, is only partially resolved and still leaves exposure. Scoring, the audit states, restricts attackers without stopping them, and the colocation penalty is mostly useless where IPv6 addresses are plentiful. For Bus Nodes, scoring damps misbehaviour but does not control admission. Caveat: the Go code of 2020.
@2022-prunster-ipfseclipse :: This end-to-end eclipse attack ran on the live IPFS network, and its authors place the flaw in libp2p, not in IPFS itself. The libp2p connection manager trimmed peers by a score an attacker could inflate, and the Kademlia DHT kept a peer only while a connection stayed open. With pre-generated identifiers, the attacker poisoned a node's routing table within minutes and eclipsed an average node within an hour with about 75 percent probability (CVE-2020-10937). Mitigations reached go-ipfs 0.5 in April 2020, before public disclosure in October 2020. Bus Node discovery and connection limits come from the same library family. Caveat: go-ipfs 0.4.23 with the go-libp2p of 2020, not rust-libp2p 0.57.
@2022-kumar-gossipsub-formal :: The first formal model of GossipSub, built in the ACL2s theorem prover and endorsed by the protocol's developers, states three properties of the score function: it is fair, penalises bad behaviour and rewards good behaviour. Fairness is proved in general; the other two depend on configuration. Under the Eth2.0 parameters the authors construct attacks, on any topology, in which peers never forward topic messages yet keep positive scores and are never pruned. The Filecoin parameters satisfy all three. Weights that hold on one network can fail on another, so Bus Node score parameters need a check of their own. Caveat: the model covers v1.1 scoring, not the whole router.

## Source anonymity, propagation privacy and spam resistance

Source anonymity means an observer cannot tell which node first sent a message. Midnight Express seals content, but a relay still sees which neighbour handed it an Envelope, and when. The same relay must refuse excess traffic, and counting messages per sender requires knowing the sender. Four lines of work bear on both problems: identity counting, first-hop and timing attacks, the Dandelion stem, and the rate-limiting nullifier (RLN) constructions this design follows for admission. The requirement set therefore makes no sender-anonymity claim against relays and no timing privacy claim at launch. Whether an optional stem is worth its delay is open.

@2002-douceur-sybil :: This paper named the Sybil attack: without a logically central authority vouching for identities, one entity can present many. Its lemmas show that identity validation, direct or indirect, works only under unrealistic conditions such as equal resources across entities and simultaneous validation. Any defence that counts peers, as GossipSub's mesh selection and scoring do, is open to Sybils unless identity is tied to a scarce resource. This design therefore binds admission to a membership recorded on the ledger, not to a peer key. Caveat: an impossibility argument over a deliberately abstract resource model.
@2014-biryukov-deanonymisation :: This attack links Bitcoin transactions to the IP addresses of clients behind NAT by fingerprinting each client's entry nodes, which it learns from the client's address advertisements. A few machines with at most 50 connections to each server identify the source of 11 percent of transactions, or 60 percent if the attacker accepts a slight denial of service, at an estimated cost under 1,500 EUR a month. A Publisher's first-hop Bus Nodes form the same kind of fingerprint, and sealing content does not hide the sender. Caveat: Bitcoin's 2014 relay rules.
@2016-neudecker-timing :: This timing analysis infers the links of a flooding overlay from when a well-connected observer receives each relayed transaction. On live Bitcoin it recovered peers' links with precision and recall of about 40 percent each. It also shows that badly chosen trickling parameters, meant as a defence, can make inference easier. A Bus Node that relays every Envelope immediately exposes its mesh the same way: the topology leaks along with the timing, and it tells an eclipse attacker which nodes to target. Caveat: Bitcoin relay of that period, without mesh scoring.
@2017-fanti-anonymitybitcoin :: This paper analyses source anonymity in Bitcoin's broadcast against an eavesdropping supernode on d-regular trees approximating the real topology. It covers both trickle spreading (before 2015) and diffusion with independent exponential delays (after). Both give poor anonymity with similar detection probabilities, so the 2015 change bought little, and simulation on a 2015 snapshot of the Bitcoin graph agrees. Random delays on a gossip mesh are therefore no source-anonymity mechanism. Caveat: an eavesdropper on idealised regular trees.
@2017-venkatakrishnan-dandelion :: Dandelion splits broadcast into two phases. A transaction first travels along a random line (the stem), each hop forwarding it to one peer, and then spreads by ordinary flooding (the fluff). Anonymity is measured as the precision and recall of spies controlling a fraction p of nodes. The paper proves that any protocol allows spies an expected precision of at least p² and recall of at least p, and Dandelion comes close to these bounds. It is the reference point for any stem in front of a GossipSub mesh. Caveat: the spies are honest-but-curious and do not know the stem graph; later work relaxes both assumptions.
@2018-fanti-dandelionpp :: Dandelion++ shows that Dandelion breaks when spies disobey the protocol or learn the stem graph. Its repair has four parts: an approximately 4-regular anonymity graph instead of a line; a pseudorandom choice by each node, per epoch of about 10 minutes, to relay or diffuse; one fixed outbound edge for each inbound edge; and a fail-safe timer that diffuses any stem transaction that does not reappear. The paper analyses graph-learning, intersection, graph-construction, black-hole and deployment attacks, and runs on Bitcoin mainnet. A Midnight Express stem would copy this design and pay its delay. Caveat: the guarantees bound spy precision, not a global observer.
@2022-taheri-waku-rln-relay :: WAKU-RLN-RELAY adds rate-limiting nullifiers to Waku Relay, a thin layer over GossipSub, so relays drop excess traffic without learning who sent it. Membership is registered in a contract while messages and their storage stay off chain, so publishing costs no gas; the example epoch is 30 seconds. Proving membership in a group of 2³² members takes about 0.5 s on an iPhone 8 and verifying it about 30 ms; the prover key is 3.89 MB, and a membership tree of depth 20 costs 67 MB per peer to store. It is the closest deployed analogue of the Admission Proof and its ledger-held membership. Caveat: the evaluation is rough, and each relay detects violations locally.
@2022-vac-rln-v1-spec :: In the RLN v1 specification, members register an identity commitment in a Merkle tree. A member's secret a0 is the intercept of a line y = a0 + x·a1 whose slope a1 hashes a0 with the external nullifier (epoch and application). Each signal carries a zero-knowledge membership proof, a point (x, y) on that line, and an internal nullifier that repeats if the member signals twice in one epoch. One point leaves the line undetermined. Two fix it and reveal a0, so overuse exposes the secret and any stake. The Admission Proof follows this shape, with one admission nullifier per Envelope. Caveat: enforcement needs both points to reach one verifier. The design is to be tested in a proof of concept (Chapter 9). In it, one membership spent its single credit for the largest class (16,384 B sealed bodies) on conflicting Envelopes sent at once to two, and then to five, ingress Bus Nodes, and each node accepted the one it saw first (2 of 2, 5 of 5). The quota therefore holds per Bus Node, not network-wide, and the kept Envelopes are evidence for revoking the membership.
@2023-sharma-p2panonymity :: This Bayesian framework gives each transaction a probability distribution over its possible originators, built from what colluding nodes observe, and scores anonymity by its entropy. Applied to Dandelion, Dandelion++ and the Lightning Network, it finds that none offers acceptable anonymity. In Dandelion, an adversary controlling 15 percent of nodes is left with about eight candidate originators on average, and a larger network does not enlarge the anonymity set. A Dandelion stem on Midnight Express would therefore not give sender anonymity; at most it raises the cost of identifying the first Bus Node. Caveat: simulated topologies and idealised protocols.
@2023-guerraoui-inherent-anonymity-gossiping :: This paper analyses gossip source anonymity with differential privacy. It bounds what any gossip protocol can offer on an arbitrary graph: on poorly connected graphs, no protocol gives the source meaningful ε-differential privacy. It then proves that cobra walks on well-connected graphs do, with a tight trade-off between dissemination time and anonymity, and the technique extends to Dandelion. The requirement set claims no source anonymity from GossipSub propagation for this reason: a fast mesh spends the dissemination time that anonymity needs. Caveat: an abstract gossip process, not GossipSub's mesh and control messages.
@2024-vac-rln-v2-spec :: RLN v2 generalises the rate limit from one message per epoch to a message limit per epoch, and each proof carries a message identifier below that limit. RLN-Same has one limit for all members. RLN-Diff sets a limit for each member from public data such as stake or reputation. Midnight Express takes the RLN-Diff form but registers four limits per membership, one for each Envelope size class (sealed bodies of 256 B, 1,024 B, 4,096 B and 16,384 B): 64, 16, 4 and 1 Envelopes per 60-second admission window respectively. Caveat: the specification has raw status, the earliest stage of the Vac specification index, so it may still change. The design calls for a zero-knowledge proof of this relation, and no proof system has been selected. The reference implementation checks the relation with a stand-in whose secrets every Bus Node can see, so in the prototype relays can link each Envelope to its member and admission is not private. Its 4.5 ms verification cost is a synthetic delay, not a measured proof system.
@2025-waku-dandelion-spec :: This Logos specification, also at raw status, places a Dandelion stem in front of Waku Relay, which runs on GossipSub. At the start of each 10-minute epoch every node picks stem or fluff state at random. A stem-state node selects two stem relays per pubsub topic from its mesh and maps each incoming stem connection to one of them for the epoch. Stem messages travel over Lightpush, so GossipSub scoring is unaffected, and a node's own messages always start on the stem. It is the most direct template for an optional stem on Midnight's Shards. Caveat: it knowingly departs from the analysed Dandelion++ to tighten latency, and includes no evaluation.

## Midnight and Cardano network research

Midnight Express runs beside a Midnight node and keeps membership, quota roots (Merkle roots over registered memberships, against which Admission Proofs are checked) and Anchors on Midnight's ledger. Mainnet ran ledger 8.0 as of 4 August 2026. The node code pins ledger 9, which brings the contract events Midnight Express uses for its Anchors, and the published documentation still describes an earlier generation. Kachina and Zswap fix what the ledger offers, CougaR and SecureCyclon address the overlay, and the Leios analysis names two attacks the overlay must survive. None was measured on Midnight's network, so each carries over as a design argument and none of its numbers transfer. Which of these mechanisms ledger 9 and the adopted GossipSub parameters permit is open.

@iog-kachina-foundations-of-private-smart-contracts :: Kachina models private smart contracts in the Universal Composability framework. Each contract has a public state on the ledger and a private state held by each party, and a transaction is a zero-knowledge proof that some private state and input justify the change to public state. A transaction's state oracle transcript records the queries it makes and the answers it expects. The transaction applies in any state that gives those answers, so concurrent transactions do not invalidate each other unless one changes an answer the other relies on. Midnight's Compact contracts follow this model. Midnight Express can therefore reach a contract, such as the Bus Registry recording memberships and Anchors, only through public state, proofs and disclosed values. Caveat: the model treats the ledger as ideal and ignores network metadata, and Compact's details postdate the paper.
@iog-cougar-fast-and-eclipse-resilient-dissemination-for-blockcha :: CougaR, from IOHK-funded work on Cardano's overlay, builds each node's outgoing links from close links, chosen for low latency, and random links; the mix spreads blocks faster than either kind alone. A node chooses all its outgoing links itself, so others can never impose all of them, which is the condition eclipse attacks exploit. In the Bitcoin topology, 20 close plus 20 random links reach 95 percent of nodes only 1.44 times slower than an ideal one-hop broadcast. Bus Node peer selection can adopt the rule through GossipSub's D_out quota. Caveat: simulated block dissemination, not measurements on Midnight's network.
@iog-securecyclon-dependable-peer-sampling :: SecureCyclon, also funded to secure Cardano's overlay, hardens the Cyclon peer-sampling protocol against the hub attack, in which malicious nodes fill honest views with links to themselves. Node descriptors become signed communication certificates, so a node that over-represents itself leaves verifiable proof of misconduct and can be blacklisted. Over-representation is eliminated deterministically, a stronger guarantee than a bound on it, and the protocol holds in simulation with 40 percent of nodes malicious. It is a candidate for Bus Node peer discovery if eclipse tests show views being captured. Caveat: simulation only, and Sybils can still create many signing keys.
@2024-midnight-zswap-spec :: In Midnight's draft specification of Zswap, the shielded token in its ledger, coins exist as commitments in a Merkle tree and spends as nullifiers in a set, so the set of unspent coins is never computable. The ledger keeps a time-indexed history of tree roots so that proofs against older roots stay valid. Midnight Express reuses two of these ideas: admission nullifiers, and a bounded window of accepted roots (cached roots expire after 25 hours). Caveat: a draft, so each detail needs checking against ledger 9.
@iog-high-throughput-permissionless-blockchain-consensus-under-re :: The Leios paper models gossip networks with two adversarial behaviours earlier models ignored. In a message burst, withheld messages are released at once; in an equivocation, many versions of one message spread. Leios relays the freshest messages first, so old messages cannot delay new ones, and guarantees that a proof of equivocation reaches every honest party within a bounded time. Both behaviours apply to Midnight Express. A 48-hour Envelope lifetime invites bursts of old Envelopes, and conflicting Envelopes under one admission nullifier are equivocations whose evidence must spread. Caveat: a Cardano consensus design, not part of Midnight's partner-chain consensus, analysed rather than measured.
