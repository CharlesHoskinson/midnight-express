# SDK, adapters and failure semantics review

Reviewed `dist/index.html` and `dist/app.js` against `docs/product-requirements/recommended-stack-and-use-cases.md`. The presentation is broadly faithful, but several developer-facing connections are implicit.

1. **Make application-owned adapters visible.** The SDK mentions application adapters, but neither the map nor the journey explains the required mapping of source identity, version, snapshot/delta and finality. Add an adapter description connecting RFQ applications, ERP/payment status and bounded agent approvals to authenticated event schemas. State that connector evidence authenticates source claims; application policy authorizes effects.
2. **Expose the receiver SDK contract.** `components.sdk` lists cancellation, `on/off/once`, isolation and bounded asynchronous streams, but omits explicit failure, gap, expiry and recovery signals. Connect durable inbox/recovery back to the listener API and clarify that cancellation is local. Keep versioned private schemas and no recognition-triggered upstream selectors/automatic acknowledgements explicit in this panel, rather than requiring discovery of journey step 6.
3. **Complete retry and quarantine semantics.** “Bounded retry and encrypted quarantine” lacks retry age/budget, preserved message identity and expiry, and authorized redrive. Add these to the SDK/operations gate and connect processing failure → encrypted local quarantine → policy-authorized redrive. Retrying must not mint a new event identity or extend expiry.
4. **Add operational state visibility.** The evidence strip correctly separates admission, persistence, anchor/finality, processing and business acknowledgement. Connect these distinctions to privacy-preserving SDK/operator health reporting; a handler failure should remain isolated and should not imply successful processing or business completion.
5. **Connect adapter finality to contract notifications.** Exact carried bytes/applied-phase checks appear only in the consumer-authority panel, while source adapters and finality-aware listeners are absent. Explain provisional/retracted/final source states and catch-up/snapshot freshness at the incoming adapter boundary. Private carried-event support remains a separate gate for contract-origin notifications, not a general requirement for ordinary off-chain events.

Already accurate: `once` does not promise once-only business execution; semantic headers stay encrypted; recognition does not automatically acknowledge; signed business acknowledgement is explicit; external effects require destination idempotency or reconciliation; atomic local processing is labeled a proposed UmbraDB capability.

Incidental render defect: `app.js` reads `window.MPE_USE_CASES`, but `index.html` only loads `app.js`; neither reviewed file defines that global. Without another data loader, the ten-use-case grid renders empty, hiding the adapter-specific scopes and gates. Load the generated use-case data before app initialization.
