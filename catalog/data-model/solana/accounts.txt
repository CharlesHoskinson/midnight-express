An account is Solana's fundamental data unit for storing state. The network
stores all state in a key-value store where each key is a 32-byte address and
each value is an account.
Diagram of 3 accounts and their addresses. Includes the account structure definition.
Account Structure
Account addresses (public key, PDA), the five fields every account contains,
storage balance, and the deprecated rent field, with an interactive code
walkthrough.
Account Types
Program accounts (executable code), data accounts (program state), system
accounts, and sysvars (cluster-wide state).
Modification Rules
Runtime-enforced rules for lamports, data, owner, executable flag, and
borrows.
Account Runtime
Account loading validation, BPF serialization format, and deserialization.
Key facts
Structure
: Every account has the same

five fields
: lamports, data, owner,
executable, rent_epoch.
Address
: Each account is identified by a unique 32-byte address (either an
Ed25519 public key or a 
PDA
).
Ownership
: Only the account's owner program can modify its data or debit
lamports. Any program can credit lamports to any writable account.
Account storage
: Every account must hold a refundable minimum lamport
balance proportional to its data size to remain onchain.
